# ADR 0035: 手套買打席，手臂買先發

出賽量在兩側各自結算，來源是**該側自己的評價**：

*   投手的先發數、後援場次、局數 → `pitchingOverall`
*   野手的出賽場數、打席 → `battingOverall`

兩者的預設值都是 `ctx.overall`，因此單一定位的球員行為完全不變（`overall` 就是
`max(投手評價, 野手評價)` 加特性修正，單側球員的最大值必是他自己那一側）。分歧只
發生在二刀流身上。

差額用 `r.overall - Math.max(0, r.fielder - r.pitcher)` 的形式扣，而不是直接換成
`r.pitcher`——**特性修正必須留著**。直接換會靜悄悄地把每一位投手的特性加成拿掉，
那是一次全域位移，不是一個修正。

零出賽的那一側不生成績列：`games === 0` 時整條 `null`，而不是留一排 `0.000`／
`0.00` 的空殼。

## 背景

`playSeason()` 把同一個 `ctx.overall` 同時餵給 `proPitchingLine()` 與
`proBattingLine()`。一位打擊 80、手臂 20 的二刀流，他的棒子把 `overall` 撐到 80，
而 80 分的 `overall` 走進投手線之後買到了先發輪值、局數與勝投——**他的棒子替他掙到
了上場投球的機會**。

反向也成立，而且那一面是對的：一位守備見長的游擊手靠手套站進先發打線，站進去就會
有打席。守位與打擊不可分割，投球與打擊可分割——這是規則的形狀，不是漏洞。

同時，出賽量歸零之後仍有兩處把零當成成績：`awards.ts` 的 `min_ip_equals_games`
讓 0 局的投手符合防禦率獎資格，`game.ts` 兩處把 `p.era.toFixed(2)` 印在他從沒投過
的球季上。

## 決策

**扣的是投手側，不是野手側。** 打擊出賽量吃 `battingOverall` 只是把同一條規則寫
完整；實務上單側球員拿到的仍是 `overall`，改變只發生在二刀流的投球那一側。

`trust_factor` 與 `gamesPlayed` 因此在兩側各跑一次，各吃各的評價。信任度是「球團
今年還敢不敢用你」，那個問題投打分開問才有意義。

**一場都沒上就沒有那一側。** 空的成績列不是「0 成績」，是「沒有這件事」；顯示一個
從未投過的球季的 0.00 防禦率，比不顯示更誤導。

## 後果

*   `SeasonContext` 多出 `pitchingOverall?` 與 `battingOverall?`，兩者皆選用、皆
    預設回 `ctx.overall`。既有呼叫端不必改。
*   一位 80 棒 / 20 臂的二刀流從此拿不到先發輪值——這是刻意的行為改變，測試
    (`season.test.ts`) 直接釘住這一條，而不是留一句註解。
*   守備買打席**不修**，並在 `season.json` 的 `_side_note` 與測試裡寫成刻意的決策，
    免得下一個人把它當成同源的 bug 一起「修掉」。
*   `min_ip_equals_games` 加上 `ctx.pitching.outs === 0` 的排除；防禦率獎不再發給
    零局投手。
