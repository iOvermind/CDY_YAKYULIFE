# ADR 0029: 審判你的是你剛打完的那一季

## 背景

一位玩家回報：畫面上綜合 60、聯盟水準 55，球季結束後被下放 3A，卡片只寫「成績未達標」。三個數字沒有一個對得起來。

追下去發現不是門檻沒調好，是**判定吃到的輸入不是玩家看到的那一份**。`#proEndYear` 的順序是：

```
this.#year++;
advanceStandards(...)     // 聯盟水準推進到明年
applyAging(...)           // 能力老化
evaluateMovement(...)     // 才判定今年的去留
```

- 記分板的「聯盟水準」（`state.pro.par`）是**今年**的 55；判定拿到的是 `advanceStandards` 之後**明年**那一份，可能已經彈回 59。
- 記分板的綜合 60 是**老化前**；判定用的是老化後重算的 rating。

兩個數字都在玩家眼前被換掉，而降級卡把 `move.reason` 丟掉、改寫成一句與判定依據無關的「成績未達標」——下放看的是能力對門檻，根本不是成績。玩家沒有任何管道還原自己是怎麼掉下去的。

同一次檢查也發現下放門檻吃浮動：`hereMin = standardOf(standards, level).min + barAt(level)`。於是能力漲一分、聯盟漲兩分的球員會被下放——他做對的每一件事都沒有回報。

## 決策

**一、聯盟水準的推進排在升降級之後。** 這一季的去留用這一季的聯盟水準審。往下的合約、自由市場、挖角仍看新的一年——那些談的本來就是明年的事。

**二、老化維持在升降級之前。** 球團決定的是明年還要不要用你，看老化後的能力是對的；而且衰退卡當場就把新數字報給玩家，不是黑箱。

**三、降級與戰力外的門檻不吃浮動，升級照吃**（延續 ADR 0011 對「釋出」的原則，範圍擴及下放）。今年人才斷層就比較好擠上去，那是機會；拿浮動去踢人不是同一回事。

**四、降級卡一律報 `move.reason`**，也就是引擎判定用的那一句：`搆不上大聯盟的標準（綜合 57／門檻 60　外籍名額）`。展示層不得另編說法。

## 後果

流程裡出現一個**刻意的不對稱**：聯盟水準排在判定後、老化排在判定前。看起來像沒整理乾淨，其實兩邊的理由不同——一個是「不該用明年的尺量今年」，一個是「球團看的是明年的你，而且已經告訴你了」。不要順手把它們對齊。

升降級不對稱也一樣：升級吃浮動、降級不吃。兩者都是刻意的，理由寫在 `pro.ts` 的 `evaluateMovement` 開頭。

所有 seed 的重播結果會變。名人堂比例護欄從 24.4% 落到 21.0%（仍高於 12% 上限，見 ROADMAP U1）。

## 替代方案

- **順序不動，只把話講白。** 卡片明講「判定用的是明年的聯盟水準」。誠實了，但那個規則本身就沒道理——用還沒發生的球季審已經打完的球季。
- **老化也移到判定之後。** 判定完全用玩家看到的那個他。代價是球團等於用過期資料決定明年名單，而衰退資訊本來就已經揭露了，不缺這一層保護。
