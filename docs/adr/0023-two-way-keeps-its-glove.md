# ADR 0023: 二刀流保留守備能力，評價改用所在體系的尺

## Status

Accepted

## Context

`docs/problems.txt` #13 要求：進職業後把二刀流的守備能力拿掉——不再顯示，增減時
也不再影響，「跟選投手／野手的時候把不必要的數據拿掉一樣」。

鎖側（ADR 0009）確實是那樣做的：鎖了投手就永遠看不到守備四項，也練不到。但二刀流
跟鎖側不是同一件事。鎖側關掉的那一半是**真的關閉**了；二刀流的守備現在還在做事：

1. 決定他守不守得動某個守位（`defense_offsets` 的門檻）。
2. 守得動就登錄該守位，賽季模擬照樣算他的守備分與守備勝利份額。

現實那一面也不支持拿掉。二刀流是可以守野的——大谷在日職前期守外野，貝比魯斯常態
守外野。成熟期退成投手＋指定打擊的理由是投球日的負荷與傷害風險，不是「他不會守」。
把守備能力整組收走等於宣告「二刀流不存在守野這條路」，那比現況離現實更遠。

查證途中另外發現兩件事。

**捕手的死角。** 二刀流的起始守位必定是 UTIL（ADR 0009：UTIL 是二刀流的唯一入口），
而 `scanListFor('UTIL')` 走 `[...IF, ...OF]`——內外野兩條光譜全掃，唯獨掃不到捕手。
捕手自成一路，只有「當前守位是 C」或「起始守位是 C」的人進得去；而起始守位選 C 的
人被 `sideOfStartPosition()` 鎖成野手側，從開局就不可能變成二刀流。**「二刀流捕手」
因此在結構上不存在**，不是掃描漏了他，是兩道規則夾出來的死角。

**評價用錯了尺。** `rate()` 的守位由 `ratingPosition()` 推定，而參照層級硬寫在
`game.ts` 裡：

```ts
export const TWO_WAY_REFERENCE_LEVEL = 'CPBL1';
```

守備門檻是「該層級 par + 位移」，層級越高門檻越高。旅外的二刀流因此被用中職一軍的
門檻判定守得動游擊，`twoWayPositionBonus()` 照游擊給滿額 +5——人在大聯盟，量他的卻
是中職那把尺。這個常數同時違反「可調參數一律進 JSON」，而且它要的答案 ADR 0021 的
`#benchmarkLevel` 早就會算了。

## Decision

**二刀流的守備能力全部保留，繼續顯示，繼續參與加減。** #13 的「拿掉」不採納，理由
如上：它還在做事，而且現實裡二刀流會守野。

**評價的參照層級改為 `#benchmarkLevel`**，刪除 `TWO_WAY_REFERENCE_LEVEL`。養成期
`#pro === null` 時它回 `homeBenchmarkLevel()`，由 `leagues.json` 的 `transfer.home_org`
與 `paths` 推導出 `CPBL1`——與原本硬寫的值相同，但改由資料推導；進職業後則跟著他
實際所在的體系走。評價與模擬從此用同一把尺（ADR 0021 的原則）。

`#cups()` 的養成期大賽同樣改用 `#benchmarkLevel`，該處 `#pro` 必為 null，行為不變。

## Consequences

守備品質對二刀流的**評價**仍然沒有意義——守得動就加固定分，這是 ADR 0008 已經接受
的取捨，#13 不改變它。差異體現在賽季模擬的守備分與勝利份額。想在能力表上看到守備
品質說話的人會覺得那四項「沒用」，但它們決定的是他站哪個守位，而守位決定加分多少。

旅外二刀流的野手側評價會**下修**：門檻變高，推定守位往光譜下游退，守位加分跟著減。
一個在中職量得動游擊（+5）的二刀流到了大聯盟可能只量得動三壘（+2）。這是修正而非
平衡調整——他本來就不該用母國的尺被估身價。

「二刀流捕手」的死角**留著不處理**，登記為待辦。現實裡投手兼捕手接近零例，優先度低；
真要開，要改的是 `sideOfStartPosition('C')` 的鎖側，不是掃描順序。
