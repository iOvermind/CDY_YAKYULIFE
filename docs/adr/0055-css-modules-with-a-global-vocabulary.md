# 0055. 元件的樣式用 CSS Modules，全域只留主題 token 與引擎的詞彙

日期：2026-09-26

## 狀態

已接受

## 背景

`App.tsx` 拆成各畫面的元件之後，樣式仍是一份七百行的 `app.css`，所有 class 都是全域的：改 `.tag` 要先搜遍整個介面才知道會波及誰，而檔案裡有兩成的規則早就沒有任何元素用到（舊版的三欄版型、生涯時間軸），留著沒人敢刪。

但有一批 class 不是介面自己取的名字：**引擎與規則資料會把 HTML 寫成字串**，裡面帶著 class——`<b class="hl">`、`<span class="dn">`、`<span class="sub">`，卡片的語氣也是引擎給的（`info`／`good`／`bad`／`gold`）。事件卡、特性說明、攻略都是這樣畫出來的，伺服器重跑時產出的也是同一批字串。CSS Modules 會把 class 名加上雜湊，這些字串就對不上了。

## 決策

**元件的樣式一律寫成 CSS Module，放在元件旁邊**（`Board.module.css`）。好幾個元件共用的外觀（按鈕與選單列、浮動視窗、成績表、標籤、成就櫃與攻略的區塊）各自一份共用 module，用到的元件各自 import——跨元件的選擇器（例如記分板覆寫特性列的 `.bd-traits .tag-note`）因此必須和它的目標放在同一份 module 裡。

**全域只有一份 `src/ui/global.css`，而且只收兩種東西：**

1. **主題 token**（`body[data-theme]` 底下的 CSS 變數）與 reset。生涯成績圖在 canvas 上讀的也是這些變數。
2. **引擎與資料寫進 HTML 的 class**：`hl`、`dn`、`up`。`sub` 也屬於這一類，但它沒有自己的全域規則——它的樣式看掛在哪個元件底下，module 裡用 `:global(.sub)` 引用。

卡片語氣不是 class 名：引擎只給一個值，由介面換成 module 裡的 class（`styles[entry.tone]`）。

**引擎要新增一個會寫進 HTML 的 class，就要登記到 `global.css`。** 沒登記的話不會報錯，只會安靜地沒有樣式。

## 考慮過的其他做法

- **共用外觀全放進 `global.css`**：改動最少，但全域檔會長回半個 `app.css`，「為什麼這些是全域的」就說不清楚了。
- **讓引擎改輸出語意標籤**（`<mark>`、`<ins>`、`<del>`）：要改一百五十多處引擎與資料，而且那些字串是重播與伺服器驗證的一部分，不值得為樣式動它。
- **把共用外觀抽成 React 元件**（`<Button>`、`<StatTable>`）：最乾淨，但要改寫所有用到的地方，超出這次「外觀不變」的範圍，留給之後動主題的時候。

## 後果

- 一個 class 的影響範圍就是 import 它的那幾個檔案。
- `id` 仍留在 DOM 上當錨點（`#board`、`#panel-act` 有程式在量它們的高度，INTERFACE.md 也用它們描述版面），但不再拿來上樣式。
- 從 id 改成 class 會降低選擇器的權重。這次改寫逐條比對過，同一個元素上沒有跨 module 的權重競爭。之後新增規則時，同一個元素的樣式盡量只來自一份 module。
- 型別擋不住打錯的 class 名（`styles.tagrow` 會是 `undefined`）。改樣式之後要看畫面，或用截圖比對。
