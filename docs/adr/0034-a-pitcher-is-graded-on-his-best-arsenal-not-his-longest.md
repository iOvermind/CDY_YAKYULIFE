# ADR 0034: 投手評價看最好的那組武器，不看最長的那串

球速與四項變化球合成**武器庫**一起排序。取前 n 名套第 n 組權重，四組全算過**取最
高分**：

| 採計項數 | 權重 |
|---|---|
| 5 | 0.3 / 0.25 / 0.2 / 0.15 / 0.1 |
| 4 | 0.35 / 0.25 / 0.25 / 0.15 |
| 3 | 0.5 / 0.3 / 0.2 |
| 2 | 0.6 / 0.4 |

每組加總為 1，所以武器庫分數是**一個平均水準**，再乘 `arsenal_share`（先發 0.75、
後援 0.80）才是實際佔比。剩下的份額全給控球。

體力退出投手評價。

## 背景

舊算法是「球速固定採計 + 四項變化球排序後遞減加權」，權重總和固定。它的隱含主張是
**多練一顆球永遠不會白費**——即使第四顆球只值 0.033 的權重，也是正的。

問題出在天賦上限。上限高的球員輕鬆練到三顆 70，上限低的球員每一顆都卡在 60 出頭，
卻因為「件數多」在評價上被算成同一件事的加總，反而追不上。真正該問的問題不是「你
有幾顆 70 的球」，而是**在固定的點數下你怎麼分配**：一個練成三顆 60 的投手，多練
一顆就是四顆全掉到 55。舊算法裡他因為件數多而勝出，直覺上卻反了——那是一個沒有決勝
球的投手。

同時，體力在投手評價裡吃 0.05–0.1，在野手評價裡是 0（`offense_abilities` 只有
con/pow/eye/spd，另加守備分）。同一個能力值在投打兩條路上價值天差地遠，而體力早就
在出賽場數、投球局數與受傷機率上結算過了。評價再算一次是重複計價。

## 決策

**武器庫是平均水準，不是件數。** 因此：

*   同水準的第四顆球不加分。三顆 70 與五顆 70 同分。
*   要加分只有一條路：練出比現有更好的一顆球。
*   點數攤薄會扣分。三顆 60 攤成四顆 55 是淨損。
*   上限低的人靠多練球種**逼近**上限高的人（五顆 62 勝過一顆 70），但不會超車。

「取最高分」是這套辦法的關鍵。少了它，只有一顆決勝球的火球男會被三顆爛球用五格權
重稀釋掉；有了它，他自己落在兩格那組，被誠實地評成「兩樣武器，樣樣頂」。球種數因
此**徹底不是一個離散門檻判定**（ADR 0005 的原則不變），而是球員自己落在最適合他的
組數上。

體力併進控球的份額，不另立權重。

## 後果

*   尺規沒有整體位移：新舊權重總和都是 1，六項全 70 的人前後都是 70。動的是分佈——
    偏科型（少而精）往上、廣而不精往下、均衡型不動。門檻（`benchmarkLevelOf()`、
    球探、簽約）不必重校，guardrail 全綠。
*   `PitcherRoleWeights` 從 `velocity_weight` / `stamina_weight` / `pitch_weights`
    收斂成 `arsenal_share` / `control_weight` / `discount`。
*   牛棚分（`bullpenScore()`）不受影響——它問的是不同的問題（他適不適合關門），仍以
    球速為主。
