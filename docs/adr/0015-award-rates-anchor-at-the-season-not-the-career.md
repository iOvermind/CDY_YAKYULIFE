# ADR 0015: 獎項取得率的靠點在球季層，生涯取得率是推導出來的

## Status

Accepted

## Context

`calibrate.ts` 一直用**生涯取得率**當獎項的校準靶——「跑完一輪生涯，拿過這個獎至少
一次的比例」。實測（balanced 策略，300 輪）：

```
all_star        99.0%    batter_of_year  72.4%    rbi_king    46.8%
mvp             34.3%    rookie_of_year  23.2%    obp_king    11.8%
gold_glove       8.1%    batting_king     6.7%    hr_king      1.0%
```

這組數字沒辦法判斷任何一條線對不對。`hr_king` 1.0% 與 `batter_of_year` 72.4% 相差
七十倍，但兩者都可以講成「感覺差不多」，因為生涯率沒有共同參照——它是
「球季取得率 × 生涯長度」的複合，而生涯長度分佈是別的決定的產物。ADR 0013 才剛動
過 `stamina` 與出賽數，生涯長度就整個位移；若靶定在生涯層，每次動到無關的東西都得
重調獎項門檻。

球季層有共同參照。這類獎是「聯盟第一名」，線就該落在單季分佈的極右端。把線疊回
單季份額分佈上量：

```
batter_of_year   線 11.0～14.9（base 13）   單季份額 p50 13.1  p90 19.1  p99 22.6
                 跨過下緣的球季佔 63.1%     → 線落在 p49.2
mvp              線 17.8～24.1（base 21）   單季份額 p50 16.9  p90 25.5  p99 30.7
                 跨過下緣的球季佔 45.5%     → 線落在 p70.3
```

**`batter_of_year` 的線落在單季分佈的中位數上。**一個「年度最佳」的獎，主角有六成
的球季跨得過去。這在生涯層只顯示成「72.4%」，看不出它壞在哪裡；在球季層一眼就看得
出來。

靶值本身也能從球季層推導，生涯層不行：一個聯盟一年一座，對手池 n 人，平均球員的
球季取得率就是 `1/n`（30 隊打者獎 = 1/270 ≈ 0.37%）。主角比平均強，所以該高於它，
但高多少是可以講理的。生涯層沒有這種推導起點。

## Decision

**獎項校準的靶定在球季層：一個合格球季拿到某獎的機率。生涯取得率降為推導輸出。**

「聯盟第一名」型的獎，線該落在單季分佈的 p99 附近——這與 ADR 0014 的極值推導是同一
件事的兩種說法：p99 是從資料側看，`μmax(對手池)` 是從模型側看，兩者該對得上，對不上
就是其中一邊錯了。

`calibrate.ts` 照舊印生涯取得率，但它是**讀數不是靶**。護欄斷言改斷在球季層。

## Consequences

生涯取得率會隨生涯長度的改動而漂移，而那是正確的：球員活得久就該拿得多。不再需要
因為動了 `stamina` 就回頭重調獎項門檻。

得到一個交叉檢查：同一條線可以從資料側（單季 p99）和模型側（極值表）各算一次。兩者
不合就是 `σ_d`、對手池大小、或尺度係數 `k` 其中之一有問題。

「合格球季」的定義變成校準的一部分。現行 `min_pa` 是每個獎各自寫的（350 / 300），
那組數字現在承擔了它原本沒有的重量——它決定分母。

`all_star` 99.0% 這類保底型的成就不吃這個靠點，它們不是「聯盟第一名」。獎項保底規則
直接決定分級分佈（拿過 MVP 或年度最佳投手就保到明星帶），那條線與門檻是分開的兩件事，
不要混在一起校。
