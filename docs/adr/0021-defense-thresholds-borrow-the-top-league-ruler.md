# ADR 0021：守位門檻一律借頂級聯盟的尺，二軍與養成期都有暫定守位

## 狀態

已採用。取代 ADR 0010 裡「只有頂級聯盟設守位門檻」的那一段。

## 背景

原本的規則是：`leagues.json` 只有頂級聯盟填 `top`（門檻表），因此
`baseThreshold()` 對二軍與更低的層級一律回 `null`，`canPlay()` 就變成「二軍不
挑守位——守備再差也守得動」。連帶的結果是二軍球員沒有登錄守位，也沒有任何守
位可顯示。

玩家的回報（`docs/problems.txt` #4）：「養成／二軍要有野手守位」。介面當時的
權宜之計是自己拿頂級聯盟的門檻現算一份守位來顯示——引擎說沒有，介面卻畫得出
來，兩邊各算各的。

真正的問題是那個 `null` 講錯了事情。「守不守得動游擊」問的是**對上這項運動的
標準**，不是對上他這季剛好待在哪一層。二軍的游擊手不會因為在二軍就突然守得動
——他只是還沒被要求去守一軍的球。

## 決定

1. `baseThreshold(position, level)` 借**同體系頂級聯盟**的門檻表
   （`benchmarkLevelOf()`）。任何層級都有門檻，只有查不到體系時才回 `null`。
   要問「這一層自己的門檻」時用 `localBaseThreshold()`，目前只有算守備分基準
   的 `positionAverage()` 在用——守備分是跟同層對手比，那才該用當層的尺。
2. 引擎給出**暫定守位**（`Game.#fieldPosition`）：登錄守位優先，沒登錄
   （養成期、二軍）就用同一套掃描規則現算。差別只在不登錄、不經球員選擇，
   每次讀取都重算——那兩個階段的守備能力天天在動。

   > **修正（#32）**：本條原本還寫「不寫進生涯紀錄」，那是錯的。生涯表的守位欄
   > 問的是「這個人當年站哪裡」，養成與二軍那幾列留白等於在說他沒上場。暫定守位
   > 現在會在**當季結算那一刻**存進 `SeasonRecord.position` 與
   > `AmateurSeasonRecord.position`；存當下的值而不是引退時回算，因為它每年重算，
   > 事後問只會拿到最後一年的答案。
3. 純投手在**養成期**的守位是 DH——學生棒球的投手照樣站打席，打擊成績要有位
   置可標；進了職業之後回 `null`，那裡的純投手不該有野手成績。姓名列一律只寫
   `P`：寫 `P＋DH` 會把他說成二刀流，他只是還沒被免除打擊而已。
4. 出賽勞損與守備分吃的都是這個位置，介面不再自己算一份（`PlayerState.position`
   ／`positionName`／`positionTentative`／`playsField`）。

## 後果

- 二軍不再是守備的免罰區。守不動游擊的人在二軍也會被掃到別的守位或 DH，升上
  一軍時看到的守位不會突然變一個。
- 跨體系移動時借的是**新體系**的頂級聯盟，門檻會跟著換——那正是「換一個聯盟
  重新被評價一次」該有的樣子。
- `positionAverage()` 仍用當層的尺，因此守備分的量尺沒有被這次改動移動。
