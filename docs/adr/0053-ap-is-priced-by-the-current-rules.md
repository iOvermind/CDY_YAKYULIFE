# 0053. AP 依現行規則定價，認不出的舊成就直接刪除

日期：2026-09-26

## 狀態

已接受。

## 背景

成就表的 `points` 是解鎖當下寫死的，`ON CONFLICT DO NOTHING` 讓它永遠不會回頭重算；餘額是那一欄的 SUM 減去花掉的。於是每次改分數算法，舊帳號都留著舊規則的點數——#62 的 854 AP 就是這樣來的，那次是清空資料庫解決的。之後每次調成就 AP 都會再遇到一次。

重跑舊生涯來重算走不通：跨版本不保證能重現（[ADR 0002](0002-deterministic-rng-and-replay-log.md)）。

## 決策

- **AP 依成就 id 用現行規則重新定價**，餘額 = Σ 現行定價 − 花掉的。定價函式 `priceOwned()` 放在引擎裡，與 `evaluateAchievements()` 讀同一份設定。`points` 欄保留解鎖當下的值，只是歷史，不再參與計算。
- **階梯**（累積、生涯分級）同一族加總等於最高那一階的總額；較低的階顯示的是比它下面一階多出來的量。
- **國際賽與養成盃賽的名次在名稱裡**（id 只掛賽事名），定價從名稱剝名次。同一賽事拿到更好的名次時，結算把那一列的名稱改成新名次，差額自動補上——以前 id 相同，冠軍永遠補不到季軍之後的差額。
- **現行規則認不出的成就直接刪除**：特性被拿掉、獎項代碼或聯盟消失、累積項目消失、名次剝不出來、舊的 id 格式。伺服器每次啟動時掃一次（跟 `schema.sql` 同一個時間點），每刪一列記一行日誌。
- **餘額可以是負的**：顯示負數，已買的天賦照常生效，買不了新的，退款照退。不自動退天賦、不把餘額夾成 0。
- 「第一段生涯」改看有沒有結算過的生涯，不看成就表是不是空的。
- 不另外通知玩家 AP 變動，改版內容寫在 CHANGELOG。

## 後果

- 調成就 AP 不必再寫資料遷移，也不會再有 #62 那種殘留；改完部署，所有帳號立刻照新規則算。
- **調低某項成就的點數會讓玩家的餘額變少，甚至變負。** 這是刻意的：AP 是跨局的貨幣，讓舊規則的價錢永久留著等於兩套幣值並存。
- **刪除不可逆。** 改 id 格式或拿掉某個特性之前要想清楚：沒有寫遷移把舊 id 改成新 id 的話，那些成就在下一次啟動時就消失了。聯盟正名那次（schema.sql 裡的 UPDATE）就是該寫遷移的例子。
- `careers.ap_gained` 仍是那一局當時實際拿到的量，與現行定價無關。

## 替代方案

- **維持凍結、改版時寫遷移重算**：每次改分數都要記得寫，#62 證明了會忘。
- **認不出的成就算 0 並隱藏，不刪**：可以反悔，但資料庫會累積一堆沒有意義的列，而且「看不到卻還在」比「刪掉」更難解釋。
- **負餘額時暫停天賦或自動退款**：改版的代價全落在玩家身上，也違背「買到的天賦永久啟用」。
