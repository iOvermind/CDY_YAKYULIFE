# ADR 0001: 系統架構重構為 Tauri + React，並採用兩棲防護機制

## Status
Accepted

## Context
本專案原本為單一檔案的靜態網頁（Vanilla JS + HTML）。為了未來支援「成就點數系統」、「進階生涯數據」、「歷史生涯追蹤」以及「多重聯盟拓撲」，必須引入本地資料庫與元件化的前端架構。同時，為了發行桌面版，我們決定引入作業系統原生封裝技術。防作弊問題也伴隨線上成就系統而來。

## Decision
1. **前端框架**：放棄單一 HTML，採用 **Tauri + React (Vite)** 進行全端重建。這能保持網頁版的存取便利性，又能透過 Tauri 打包極輕量的桌面端執行檔。
2. **資料解耦**：將所有的常數設定、隨機事件、天賦規則，全面抽離為 `json` 格式，引入 Rules Engine (規則引擎) 取代寫死的分支判斷。
3. **兩棲資料庫與防作弊機制 (Progression Isolation)**：
   - **成就點數同步 (PVE)**：允許離線遊玩的桌面端使用 Tauri 寫入本機 SQLite。結算時，桌面端透過雜湊加密產生 Token 送往 PostgreSQL 伺服器同步點數。接受部分軟性作弊風險，因為這只影響單機遊玩的開局天賦難度。
   - **全球排行榜 (PVP)**：任何「離線/本地」產生的生涯紀錄一律被隔離，不允許上傳排行榜。要進入天梯排名，必須連線進行遊戲（伺服器即時驗證），實行最嚴格的隔離機制。

## Consequences
- **Positive**:
  - React 元件大幅增加開發效率，能輕鬆實作歷史生涯比較表格與天賦商店。
  - Tauri 打包體積遠小於 Electron。
  - 將核心邏輯資料化，不再需要每次擴編聯盟或天賦都大改源碼。
- **Negative**:
  - 開發流程變為需要 Node.js 與 Rust 環境。
  - 需要開發一套本地端與伺服器端同步 Token 的驗證機制。
