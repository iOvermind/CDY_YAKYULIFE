# ADR 0028：先對自己回答，再對球團回答

## 背景

ADR 0027 把季末順序整成「先外後內」之後，引退詢問仍留在最後：

```
記帳 → 海外挖角／入札 → 母隊續約 → 下放遞約 → 引退選擇
```

留在最後的理由寫在程式註解裡：「先知道明年有沒有球打、在哪裡打，再決定要
不要走。」聽起來合理，實際玩起來不是——回報 #31 的原話是「都在我選擇續約後
才問我要不要退休」。玩家剛簽下一紙三年約，系統接著問他要不要掛靴，這兩句話
擺在一起是矛盾的。

問題出在把兩種引退混為一談：

- **自主引退**是一個人先對自己回答的問題。他不是在比較選項，他是在決定還想
  不想打。
- **被迫引退**才需要先看外面——沒人續約、被下放到不能接受的層級，那是別人
  替他決定的。

原本的順序把第一種當成第二種處理。

## 決定

`#retirementChoices` 拆成兩半：

1. `#voluntaryRetirement` — 高齡的每季自主引退，以及身體發出訊號的那一年。
   排在季末的**最前面**，緊接在 `#seasonLedger` 之後、`#endOfYearChoices`
   之前。答「再拚一年」才會看到後面的挖角與談約。
2. `#retirementChoices` — 只剩「被下放，不願接受」那一問。它必須知道自己被
   送去哪一層、有沒有別的球團接手（`#demotionOffers`），因此留在最後。

季末順序因此是：

```
記帳 → 自主引退 → 海外挖角 → 母隊續約 → 入札 → 下放遞約 → 不願下放的掛靴
```

`#askRetire` 多收一個 `stayNext`：答「再拚一年」之後要接哪裡，由呼叫端決定，
不再一律跳回 `#proYear`。

第三件事：自主引退一年只問一次，但談約談到一半才發現「我不想再簽了」是真的
會發生的事，而那時候玩家手上只有簽或不簽兩個鍵。所有合約問句
（`#askTerms`、`#freeAgency`）因此永遠多掛一個引退選項，年齡門檻與獨立問句
同一條（`retirement.voluntary_from_age`）——年輕人不給一鍵結束生涯的按鈕。
這條路照樣走 `#payBuyout('player')`：延長合約是在約還沒到期時談的，中途走人
要付七成；續約與減薪回原隊的約已到期，買斷算出來是 0。

## 後果

- 說「再拚一年」之後才談約，兩句話不再打架。
- 選擇繼續打的人**仍然可能被迫退休**：談約談不成走 `#faMarket`／`#fallback`，
  下放不能接受走 `#retirementChoices`，結局一樣是引退，但那是被決定的，不是
  自己選的——而這正是兩者該有的差別。
- 抽取 `asksRetirement()` 的位置跟著往前，同一顆種子的生涯會與舊版不同。
  這是流程改動的必然代價，不是回歸。
- 測試 `自主引退問在合約與挖角之前` 守住順序：同一年裡自主引退的問句必須排在
  任何 `fa:`／`term:`／`market:`／`transfer:`／`posting:`／`demote:` 問句之前。
  「被下放，不願接受」靠標題排除。
