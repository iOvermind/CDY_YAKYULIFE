# ADR 0010：守位門檻由聯盟 par 推導，不逐聯盟手填

## Status

Accepted

## Context

守位門檻原本是一張逐聯盟手填的表，`positions.json` 的 `defense_thresholds`
給每個守位各寫一組數字：

```
"SS": { "CPBL1": 50, "NPB1": 58, "MLB": 64 }
```

只寫了三個聯盟。但頂級聯盟有六個——`leagues.json` 的 `levels` 裡有 `top` 的
還包括 KBO1、LMB、ABL。查不到門檻時 `requiredScore` 回傳 `null`，而 `canPlay`
遇到 `null` 無條件放行：

```ts
return required === null || defenseScore(ability, position) >= required;
```

於是在韓職一軍、墨西哥聯盟、澳洲棒球聯盟，**守備零分的球員會被登錄為游擊手**。
掃描順序 `SS → 2B → 3B → 1B` 的第一個就通過，沒有任何一關擋得住。跨聯盟轉會
上線之後（ADR 0004）六個體系全部可達，這條路是走得到的。

放行本身不是錯的。`defense_thresholds._note` 寫過「只在頂級聯盟設限，其餘層級
不限制」——二軍與小聯盟不挑守位是設計。錯的是這個設計被實作成「查表查不到」，
於是**漏填的頂級聯盟和刻意不設限的二軍長得一模一樣**，程式分不出來。

補數字可以解決眼前三個聯盟，但下一個聯盟上線時同樣的洞會再開一次。

## Decision

門檻改由該層級的 `par` 推導，只保留一組守位位移：

```
門檻 = leagues.levels[level].par + positions.defense_offsets[position]

C +1   SS +5   CF +4   2B 0   3B −2   RF −3   LF −6   1B −11
```

位移取自 NPB1 與 MLB。**這兩個聯盟相對於各自 par 的位移本來就完全相同**，
那已經是一條規則，只是沒寫下來；本 ADR 只是把它講明並套用到全部。

「只在頂級聯盟設限」改由 `levels[level].top === undefined` 判斷，不再靠查表
失敗來表達。缺資料因此不再長得像沒有要求。

推導函式 `baseThreshold` 放在 `rating.ts` 而非 `defense.ts`：後者依賴前者，
反向 import 會成環，與該檔 `TWO_WAY_TRAIT` 的處理同一個理由。

## Consequences

CPBL1 原本的位移是 `+2 +6 +5 +2 0 −1 −3 −8`，跨度 14 而非 16，向上壓縮。
沒有任何註解解釋為什麼，看不出是刻意的模型決定還是最早手填時的殘留。一併
收進公式，門檻因此鬆 1～3 分（一壘 36→33，游擊 50→49）。

這動到校準基準線。重跑 400 局的結果：

| | 收進公式前 | 收進公式後 |
|---|---|---|
| 名人堂帶 | 7.6% | 7.8% |
| 過客帶 | 13.4% | 11.8% |
| 評價分 p50 | 98 | 99 |
| 建議分級門檻 | 246/218/145/64 | 246/220/153/66 |

方向合理：門檻鬆一點，守位保得住的年數多一點，守備側勝利份額略增。幅度小到
不足以動搖任何既有結論，但 ROADMAP 記錄的建議門檻已同步更新。

NPB1 與 MLB 的門檻一個數字都沒變——公式是從它們身上讀出來的。

代價是往後不能單獨微調某個聯盟的某個守位。真要有聯盟需要偏離（例如某個聯盟
的游擊確實特別難守），得先想清楚偏離的理由並寫下來，而不是直接改一格數字。
這正是 CPBL1 當初出問題的方式。
