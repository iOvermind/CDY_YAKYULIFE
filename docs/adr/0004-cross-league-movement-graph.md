# ADR 0004: 跨聯盟移動用推導式的圖，不列邊

## Status

Accepted

## Context

`index_legacy.html` 只有三個體系（中職／日職／美職），因此它把跨聯盟的路徑寫成三個 `if`：

```js
if (S.lv==='CPBL1' && o>=53 && ...) → NPB
if (S.lv==='CPBL1' && o>=57 && ...) → MiLB
if (S.lv==='NPB1'  && o>=60 && ...) → MLB（入札）
```

新架構有**六個**體系：CPBL／NPB／KBO／LMB／ABL／MiLB。照 legacy 的寫法，路徑數量是體系數的平方，而且每加一個聯盟就要再寫一輪。

更要緊的是：**一大批已經蓋好的機制目前是死碼。** `evaluateMovement()` 只在 `pathOf(org)` 這一條梯子上移動，沒有任何一行程式碼會改變 `org`，因此——

- `leagues.json` 六個體系的階梯，只到得了 CPBL
- `teams.json` 六個聯盟共 94 支球隊，只用得到中職那 6 支
- `hall_of_fame.json` 六座名人堂，只跑得到中職那座
- `runBallots()` 的多聯盟並存邏輯，永遠只會回傳一筆
- 代表聯盟、帽徽、跨聯盟通算、生涯里程碑，全部退化成單聯盟的特例
- **ADR 0003 的難度係數從設計以來沒有被驗證過**——它的用途正是把不同聯盟的份額換算到同一把尺上，但所有樣本都在同一個聯盟

那種程式碼放越久越危險：沒有人知道它對不對。

## Decision

**跨聯盟移動的邊由資料推導，不逐條列出。**

### 1. 方向由 par 決定：挖角往上，尋路往下

- **挖角**：能力達到目標體系的挖角門檻、通過年齡窗口、上季的勝利份額達標 → 該體系可能來挖你。
- **尋路**：被釋出或被下放時，掃描 par 不高於你能力的體系，找得到就有邀請。

一個體系要接上這張圖，只需要在 `leagues.json` 給出 par、min、挖角門檻與年齡窗口。ROADMAP 階段五想要的逆襲路徑（「在次級職棒打出鬼神成績後被美職重新挖角」）因此自然成立，不必為它寫規則。

### 2. 不限一階

中職的頂尖球員可以同時被日職、韓職與大聯盟盯上。legacy 本來就是這樣（中職直跳大聯盟，不經日職），一階一階爬的模型反而不真實。

### 3. 資格看能力與年齡，不看目前層級

legacy 用 `S.lv==='CPBL1'` 當條件，因此「在二軍的強者」不管多強都不會有人來挖。球探看的是球員，不是他登錄在哪一軍。而我們的升降級判定跑得很勤，能力夠的人本來就會被升上去，兩種寫法的結果相近——差別在於**不會出現「他明明夠強卻因為卡在二軍所以沒人看見」這種怪事**。

### 4. 一年一次挖角事件，多聯盟併成一張報價單

五個可能的目的地各自獨立跳提問的話，一個頂尖球員的某一年會連問五次。改成季末先擲一次「今年有沒有人來挖」，有的話把所有符合條件的聯盟併在同一張選單上。

玩家因此看到的是一張**可比較**的表——日職二軍 vs 大聯盟 vs 韓職一軍擺在一起，那個抉擇才有重量。而「日職和大聯盟同時來搶」正是旅外題材最好看的一幕。

### 5. 落地層級 = `min + import_premium`，`import_premium` 固定 4

被挖角不代表到了那邊還是一軍球員。落地在該體系中你的能力達得到 `min + 4` 的最高層級——綜合 57 被大聯盟挖走，MLB 需要 60，落在 3A。

那 4 點有真實依據：**外籍球員名額有限，球團不會拿一個剛好及格的外籍去佔位，他必須明顯強過本土的替代人選。** 這也讓 legacy 的兩組數字對上了——legacy 的日職落地門檻 51 對 NPB1 的 min 50，美職落地門檻 60 對 MLB 的 min 56。

### 6. 墨聯與澳職只接人，不挖人，且不看年齡

真實世界裡這兩個聯盟不派球探去搶當打之年的球星——他們接住掉下來的人。34 歲被釋出的中職球員、旅美失敗回不去的人，才是他們的客戶。

因此它們不參與挖角，只出現在尋路的邀請名單上，而且不設年齡窗口。**「當所有頂級聯盟都關門時，還有地方打球」正是它們的價值。**

副作用是解決了一個實務問題：如果它們也挖角，那張報價單上會永遠有那兩行，玩家看第三次就會略過。

### 7. 市場規模與競技水準分開

薪資**不能**從 par 推導。大聯盟的 par 只比中職高 34%，薪資卻是 8 倍起跳、頂端 34 倍——那反映的是市場規模。

這個區分對新聯盟很關鍵：韓職 par 50 高於墨聯 48，但墨聯的市場規模遠小於韓職。若薪資跟著 par 走，墨聯會變成「錢差不多但競技水準略低的韓職」，性格就消失了。實際上墨聯的角色是「**還能打球，但錢不多**」。

因此每個體系有自己的薪資設定，與 par 是兩個獨立的旋鈕。

### 8. 入札是合約期間的獨立機制，不是挖角的一種

現實世界裡入札與自由球員是互斥的兩條路，分界正是合約：

| | 球員狀態 | 誰決定 |
| :--- | :--- | :--- |
| **入札** | 還在合約中 | 母隊同意才放 |
| **海外 FA** | 合約到期 ＋ 該體系年資滿七年 | 球員自己決定 |

入札制度存在的理由就是「他還有合約，但他想走」。legacy 把兩者都塞進 `faMarket`（合約到期時一起判定），是因為它沒有把入札當成獨立機制。

因此：入札由**玩家主動申請**，母隊依年資與入札金決定同不同意；海外 FA 則在合約到期時自動成為選項。兩條路的差別玩家一眼看得懂——**要嘛求球團放你走，要嘛熬到不需要求人。**

入札的資格門檻不另設：它就是落地規則的 `min + 4`，而那與 legacy 的 60 完全一致。

## Considered Options

**照 legacy 逐條列出邊**——完全可控，行為與原版一致。否決原因：六個體系要維護三十幾個分支，而且每新增一個聯盟就要再寫一輪。更關鍵的是它不會讓已經蓋好的多聯盟機制亮起來——那正是做這件事的主要理由。

**一步一階的階梯**（只能移動到相鄰的 par 層級）——最好平衡，路徑可預測。否決原因：不真實。中職球員直接被大聯盟挖走是真實發生的事，legacy 也是這樣寫的；強迫他先去韓職再去日職再去美國，會把旅外變成一條輸送帶。

**推導式的圖，但只啟用 legacy 那三條邊**——架構到位、風險最小。否決原因：新的三個聯盟繼續是死碼，難度係數繼續無法校準，等於把這件事的主要收益推遲到不確定的將來。

**薪資由 par 推導**——少一組資料，且與難度係數共用同一個來源。否決原因：市場規模與競技水準是兩件事，混在一起會讓墨聯與韓職失去區別。

## Consequences

**正面**

- 六個體系、94 支球隊、六座名人堂全部進入可達範圍。多聯盟並存的票選、代表聯盟、帽徽、跨聯盟通算第一次真的被執行。
- **ADR 0003 的難度係數第一次可以校準**——校準腳本終於能跑出跨聯盟的樣本。
- 新增聯盟的成本降到「填一組資料」：par、min、挖角門檻、年齡窗口、薪資設定。
- 逐段成績紀錄（`SeasonRecord`）第一次真的被使用——季中交易會讓一年出現兩段。

**負面**

- 推導的邊可能產生不合理的組合（例如某個門檻設得太鬆，導致人人旅外）。列舉式的邊不會有這個問題，因為每一條都是人工核可的。**這是刻意用可校準性換取可控性**，而護欄測試與校準腳本是配套。
- 年齡窗口、挖角門檻、份額門檻、薪資設定，六個體系各一份——資料量明顯變大。規則編輯器（階段一.七）之後這會是它要面對的第一批大表。
- 換體系會重置一批狀態：守位登錄、體系年資、聯盟戰力表、新人王資格。任何以「體系」為鍵的東西都要檢查是否需要重置，漏掉會產生難以察覺的錯誤。
- 合約系統因此成為必要前置。它原本被排在後面，但轉會的四個入口裡有一個（FA 市場）掛在它上面，而它又與季中交易雙向引用（`tradeRefuse` 影響續約條件、更衣室毒瘤同時作用於兩者）。**連續三次把合約往後推、每次都附帶一句「將來要搬回去」，那不是謹慎，是在累積返工。**
