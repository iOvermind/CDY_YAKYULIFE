# ADR 0044: 只有 iOS 走分享面板，其餘一律下載

生涯成績圖的存檔走哪一條路，判準是「這台裝置有沒有別的辦法存檔」。答案只有
iOS 是沒有，因此**只有 iOS 走 `navigator.share`，其餘平台一律 `<a download>`**。

## 背景

判準已經擺過三次，每一次都是同一個回報：「桌機按下存檔，跳出來的是分享視窗，
不是下載。」

**第一版問瀏覽器支不支援分享**（`navigator.canShare`）。Windows 的 Chrome 與
Edge 兩者都支援，於是桌機吃到系統的分享面板——那裡沒有「存到下載資料夾」這件
事，使用者得先挑一個 App 才逃得出去。

**第二版問裝置是不是行動裝置**：先看 `userAgentData.mobile`，沒有就退回
`(pointer: coarse)`。這一版的問題是桌機的回報並不齊。非 Chromium 系沒有那個旗
標，只剩粗指標；而觸控螢幕的筆電與二合一就是粗指標。回報仍然是 Firefox 與
Chrome 都跳分享。

兩版錯在同一件事：**它們問的都是裝置的某個屬性，而真正要判的是「下載這條路走
不走得通」。**

## 決定

白名單 iOS，其餘全部走下載：

```
UA 有 iPhone / iPad / iPod                → 分享
UA 是 Macintosh 且 maxTouchPoints > 1     → 分享（iPadOS 的標準模式）
其餘                                       → 下載
```

iPadOS 的標準模式會把自己報成 Macintosh，所以 Mac 還要再問觸控點數：真的 Mac
是 0，iPad 不是。

## 為什麼是白名單而不是黑名單

`<a download>` 在 iOS 之外都管用，包括 Android 的 Chrome。會壞掉的平台是**列得
完的那一邊**，所以清單該列在那一邊。黑名單要窮舉「所有會誤判成手機的桌機」，那
是列不完的——前兩版就是在列它。

清單列錯的代價也不對稱：把桌機誤判成 iOS，使用者掉進一個逃不出去的分享面板；把
iOS 誤判成桌機，使用者頂多看到圖開在同一個分頁裡，長按仍然存得下來。

## 代價

Android 使用者失去分享面板，按下去只會下載到檔案夾。這是刻意的：Android 存得了
檔，而讓它走分享得先有一個可靠的「這是 Android」判準，而那個判準正是前兩版一直
沒做對的東西。真的要還給 Android，做法是在介面上多一顆分享鈕，不是回去猜裝置。
