# ADR 0002: 確定性亂數、六條子序列，與以重播日誌取代存檔

## Status

Accepted

## Context

`README.md` 對玩家承諾「同種子＋同選擇＝同一段人生」，這不是一個表面功能，而是對整個模擬引擎的架構約束：所有影響遊戲結果的亂數都必須來自可重現的序列。`index_legacy.html:373-374` 已有一套 seeded PRNG（mulberry32 變體），全部 127 個取亂數的呼叫點都走它，只有產生新種子、擲骰動畫與開局預設名這三處使用原生 `Math.random()`。

重寫時如果先寫引擎、之後才補可重現性，就必須回頭修改每一個呼叫點——所以這件事必須在寫第一行引擎程式碼之前定案。

同時，ADR 0001 的「進度隔離」需要伺服器能驗證離線生涯的真實性，但簽章金鑰只能證明「這局在本機產生」，證明不了「這局用的是原版規則、成績沒有被竄改」。

另一方面，`index_legacy.html` 完全沒有存檔功能，生涯必須一次玩完，中途關閉即全部遺失。

## Decision

**1. 確定性範圍：同版本內完全確定，跨版本不保證。**

引擎在同一個版本內對「相同種子＋相同選擇序列」必須產生逐位元相同的結果。跨版本**不保證**——種子與重播日誌都攜帶引擎版本號，新版本遇到舊日誌一律拒絕重播並明確告知，不嘗試相容。

**2. 以「種子＋選擇序列」的重播日誌取代存檔。**

不做狀態快照式的存檔。要還原一段進行中的生涯，只儲存種子碼與玩家至今做過的選擇，重播即可重建完整狀態。用途有二：意外中斷後的回復，以及伺服器端重跑驗證。

這**不是**存檔功能：玩家介面上沒有「讀取進度」選單，只在偵測到未完成的生涯時詢問是否繼續。

**3. 主種子衍生六條子序列。**

| 子序列 | 涵蓋 |
| :--- | :--- |
| `genesis` | 開局生成：初始能力、潛力天花板、出身高中 |
| `growth` | 訓練骰、蓄力槽、能力成長與衰退 |
| `events` | 事件卡的抽取與好壞判定 |
| `health` | 傷病判定、TJ 量表 |
| `season` | 賽季模擬與成績結算 |
| `career` | 選秀、合約、交易、國際賽、感情、名人堂票選 |

**歸屬規則**：一次抽取歸屬於**執行它的領域函式**，不歸屬於呼叫者。例如事件卡的 `rand` 效果要挑一項能力來加減，那次抽取在事件解算函式內執行，因此走 `events`。

**4. PRNG 沿用 `index_legacy.html:373-374` 的 mulberry32 變體。**

## Considered Options

**跨版本永久相容**——種子碼成為可永久收藏、可傳播的東西。否決原因：抽取順序形同凍結，新增一張事件卡或調整一個判定的位置都要小心翼翼，平衡調整的自由度大幅下降。對一個還在重寫、預期會頻繁調整數值的專案而言，這個代價不划算。

**單一全域序列**（即 legacy 現況）——最簡單，直接移植即可。否決原因：無法做受控實驗。重新校準守備分權重（見 `client/src/data/positions.json` 的 `_deviation`）這類工作需要「固定傷病序列、只變動另一個系統」的能力，單一序列做不到。而分流只有在第一天做才便宜，之後補等於重寫全部呼叫點。

**無狀態雜湊式亂數**（`hash(種子, 領域, 計數器)`）——理論上最健壯，抽取彼此獨立，順序改變不影響其他抽取。否決原因：127 個呼叫點各自需要一把穩定且唯一的鍵，鍵撞名會造成抽取相關，而這是一類極難發現的 bug。收益不足以抵銷這個風險。

**狀態快照式存檔**——最直覺。否決原因：它同時帶來讀檔重刷（save scumming），而重播日誌在提供當機回復的同時天然免疫——重播同樣的選擇必然得到同樣的結果，想要不同結果只能真的做不同選擇，而那本來就是玩家可以做的事。

## Consequences

**正面**

- 伺服器可用「種子＋選擇序列」自行重跑一遍並比對玩家回報的成績，不必信任客戶端的結算數字。這比 ADR 0001 原本只靠簽章金鑰強得多。
- 重播日誌只有數百 bytes，遠小於狀態快照。
- 可做受控實驗：固定某幾條子序列、只變動一條，用於平衡校準。
- 玩家得到當機回復，但得不到讀檔重刷。

**負面**

- 生涯進行到一半時若更新了 app，那個中斷的生涯無法回復。
- 朋友分享的種子碼在下一個版本可能重現不出同一段人生。README 與遊戲內的種子碼說明**必須**講明這一點，否則是對玩家的錯誤承諾。
- 每個領域函式都必須明確宣告自己用哪一條子序列；漏宣告或宣告錯誤會造成難以察覺的重現失敗。
- 引擎內**禁止**在任何影響遊戲結果的地方使用原生 `Math.random()`。純視覺用途（例如擲骰動畫的數字跳動）不在此限，但必須確保它不回寫任何遊戲狀態。
