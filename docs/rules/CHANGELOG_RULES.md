# CHANGELOG.md 撰寫規範

> 本規範規定 `CHANGELOG.md` **該寫什麼、怎麼寫**。
> 通用規範，任何專案皆適用。

---

## 1. 目的與適用範圍

### 1.1 目的

讓人在**升級之前**就知道「這一版對我有什麼差別」，以及讓版本號的遞增有可查證的依據。

### 1.2 讀者

讀者是**使用者**。`RELEASE_RULES.md` 規定 GitHub Release 頁面內文直接引用本檔內容，因此 `CHANGELOG.md` 寫給誰看，等於 Release 頁面寫給誰看。

### 1.3 記錄原則：寫「影響」不寫「實作」

每一條**必須**回答「這次升級對使用者有什麼差別」，而**不是**「程式碼改了什麼」。

| 應該這樣寫 | 不要這樣寫 |
| :--- | :--- |
| 安裝檔從 9.7 MB 縮減為 3.9 MB | 改用新的打包工具重寫 |
| 修正跨月時日期顯示錯誤一天 | 修正 `calcDate()` 的邊界條件 |
| 舊版系統需另行安裝執行期元件 | 相依 WebView2 |

內部重構、格式調整、測試補強**不記錄**，除非它改變了行為、體積、相容性或效能。

### 1.4 本規範不管什麼

- 不管版本號**該跳哪一位** → `VERSION_RULES.md`
- 不管 Release 頁面怎麼建 → `RELEASE_RULES.md`

### 1.5 強制語彙

| 用詞 | 意義 |
| :--- | :--- |
| **必須** | 不做就是不合規（MUST） |
| **建議** | 有更好的理由才可以不做（SHOULD） |
| **可** | 自行斟酌（MAY） |

## 2. 檔案位置與命名

- 檔名**必須**為 `CHANGELOG.md`，**必須**放在儲存庫**根目錄**。
- 編碼**必須**為 **UTF-8 無 BOM**，換行**必須**為 **LF**，檔尾**必須**留一個換行。
- 語言**必須**為**繁體中文**；類別標題保留英文並加中譯（見 §3.3）。
- **禁止**外拆。變更紀錄**必須**集中於單一檔案。

---

## 3. 結構

### 3.1 整體版面

```markdown
# 變更紀錄 (Changelog)

<格式與版本號規則的簡短說明>

## [Unreleased]

## [1.1.0] - 2026-08-06

## [1.0.0] - 2026-07-20
```

- 版本區塊**必須**由新到舊排列。
- `[Unreleased]` **必須**永遠存在，且**必須**在最上方。

### 3.1.1 版本導言

版本標題與第一個類別標題之間**可**放一段導言散文，說明這一版整體上是什麼——例如
「這是把重寫前的全部功能一次收成的第一版」。

- 導言**必須**回答「這一版整體是什麼」，**禁止**用來裝該進條目的內容。單一功能、
  單一修正、單一破壞性變更一律進條目，不進導言。
- 導言**可**跨多行（Markdown 軟換行），但**必須**是連續的一段，中間**禁止**空行。
- 大多數版本不需要導言。看不出來要寫什麼就是不需要。

### 3.2 版本標題格式

```text
## [<版本號>] - <YYYY-MM-DD>
```

- 版本號**必須**用中括號包住，**不含** `v` 前綴（tag 才帶 `v`，見 `RELEASE_RULES.md`）。
- 日期**必須**為 **`YYYY-MM-DD`**（ISO 8601），且為**實際發佈日**。
  - 理由：`2026-08-06` 無歧義，而 `08/06/2026` 在不同慣例下是兩個不同月份；且此格式字典序等同時間序。
- 未發佈區塊**必須**寫 `## [Unreleased]`，**不帶**日期。

### 3.3 類別

只使用以下六類，**必須**用此英中並列寫法，**必須**依此順序排列：

| 類別 | 用途 |
| :--- | :--- |
| `### Added (新增)` | 新功能 |
| `### Changed (變更)` | 既有功能的行為改變 |
| `### Deprecated (即將移除)` | 標記將於未來版本移除的功能 |
| `### Removed (移除)` | 已移除的功能 |
| `### Fixed (修復)` | 錯誤修正 |
| `### Security (安全)` | 安全性相關修正 |

- **沒有內容的類別必須整節省略**，**禁止**寫「無」。
- **禁止**自創類別。

### 3.4 條目

- 每條**必須**是單行的無序清單項目，以句號結尾。
- 每條**必須**能獨立看懂，**禁止**依賴前一條的上下文。
- 一條只講一件事；一次改動影響多個面向時拆成多條。
- 每條**必須**以粗體的**主題**開頭，接全形冒號：`- **天賦**：傷病組多了〈浴火重生〉……`。粗體只放主題，**禁止**把內容句加粗當標題——「多了「守備」那一組天賦，兩個」是內容，不是標題。
- 主題**建議**從下表挑，一條只歸一類；真的放不進任何一類時**可**新增，新增後補進這張表：

  | 主題 | 涵蓋 |
  | :--- | :--- |
  | 打擊成績 | 安打、全壘打、敬遠、打點、盜壘等打者側的成績模型 |
  | 投手成績 | 勝敗、救援中繼、局數、三振保送、投手評價 |
  | 成績 | 投打共通的成績與份額（勝利份額、ERA+／OPS+、成績欄位） |
  | 守備 | 守備分、守備份額 |
  | 出賽 | 出賽場數、先發率、體力換場數 |
  | 成長與訓練 | 訓練骰、配點、蓄力、老化與衰退、能力下限 |
  | 傷病 | 受傷機率、大小傷、復健 |
  | 守位與定位 | 登錄守位、移防、投手定位、二刀流 |
  | 養成與選秀 | 國中高中、盃賽、選秀、高中畢業的出路 |
  | 升降與合約 | 升降級、下放、合約、薪水、自由球員、轉會、入札、交易、外籍、引退 |
  | 聯盟與球隊 | 聯盟水準、球隊戰力、奪冠機率 |
  | 國際賽 | 中華隊徵召、國際賽成績與年表 |
  | 獎項與名人堂 | 年度獎項、里程碑、評價分、生涯分級、名人堂、榮譽 |
  | 感情 | 交往、婚姻、風波、外遇、孩子 |
  | 事件卡 | 事件卡的機率與選項 |
  | 天賦 | 天賦樹與各項天賦 |
  | 特性 | 隱藏特性 |
  | 成就與天梯 | 成就、AP、成就櫃、天梯 |
  | 介面 | 版面、手機、記分板、年表、成績圖、文案、更新頁 |
  | 帳號與服務 | 帳號、伺服器、部署、種子、引擎版本 |

## 4. 撰寫規則

### 4.1 Unreleased：改完就寫

- 任何**面向使用者的變更**在合併進主分支時，**必須**同時在 `[Unreleased]` 補上對應條目。
- **禁止**留到發佈當天才回頭翻 git 紀錄補寫——那是最容易漏記的時機。

### 4.2 發佈時的轉換

發佈時**必須**依序完成：

1. 把 `## [Unreleased]` 改為 `## [<版本號>] - <發佈日>`。
2. 在其上方新開一個空的 `## [Unreleased]`。
3. 確認版本號的遞增符合 `VERSION_RULES.md`（依本次出現的類別判斷）。

此流程使發佈當下只剩「改標題、填日期」這個零風險動作。

### 4.3 語氣

- 描述**結果**，不描述過程。用「已修正」「已新增」，不用「嘗試修正」。
- 對使用者用「你」。
- **禁止**出現 commit hash、issue 編號以外的內部識別碼；**可**在條目末尾加註 issue 編號。

### 4.4 破壞性變更

會使既有用法失效的變更**必須**在條目開頭標註 **`**[破壞性變更]**`**，並寫明使用者需要做什麼。

```markdown
### Changed (變更)
- **[破壞性變更]** 設定檔改用新格式，舊設定不會自動轉換，請依 README 重新設定一次。
```

### 4.5 首次建立

專案已有發佈但尚無 `CHANGELOG.md` 時：

- **必須**至少補上目前最新版本的區塊，內容為該版本已提供的主要功能（歸入 `Added`）。
- **建議**依現有 tag 逐版回填；資訊不足時**可**只回填最新版，並在該版條目註明「首次建立變更紀錄」。
- **禁止**為了補齊而杜撰未發生的變更或日期。

## 5. 範例與註解慣例

- 佔位符**必須**用角括號加繁中描述：`<版本號>`、`<YYYY-MM-DD>`。
- 範例中的虛構專案一律用 `MYAPP`，虛構版本號一律由 `1.0.0` 起算。
- **禁止**在條目中使用註解；需要補充說明時併入條目本身的句子。

完整範例：

```markdown
## [1.1.0] - 2026-08-06

### Added (新增)
- **介面**：新增匯出報表功能，可在主畫面右上角找到。

### Fixed (修復)
- **介面**：修正輸入特殊字元時畫面停止回應的問題。

## [1.0.0] - 2026-07-20

### Added (新增)
- **帳號與服務**：首個正式版本，提供完整核心功能。
```

---

## 6. 禁止事項

- **禁止**移除或省略 `[Unreleased]` 區塊。
- **禁止**使用 `YYYY-MM-DD` 以外的日期格式。
- **禁止**自創類別，或保留空的類別標題。
- **禁止**記錄不影響使用者的內部重構。
- **禁止**貼上未整理的 git log 或 commit 訊息。
- **禁止**寫入尚未發佈的功能到已發佈的版本區塊。
- **禁止**修改已發佈版本區塊的內容（發現錯誤時，在新版本以修正條目說明）。
- **禁止**外拆到其他檔案。

## 7. 檢查清單

- [ ] 檔案在根目錄，UTF-8 無 BOM、LF、檔尾一個換行
- [ ] `[Unreleased]` 存在且在最上方
- [ ] 版本區塊由新到舊排列
- [ ] 每個版本標題格式為 `## [<版本號>] - <YYYY-MM-DD>`，日期為實際發佈日
- [ ] 只使用六個標準類別，且依規定順序
- [ ] 沒有空的類別標題
- [ ] 每條都在講「對使用者的影響」，不是實作細節
- [ ] 每條可獨立看懂，單行、以句號結尾
- [ ] 破壞性變更已標註並寫明使用者需採取的動作
- [ ] 本次版本號的遞增符合 `VERSION_RULES.md`
- [ ] 已發佈版本區塊未被修改
